# T1087.001 — Local Account Discovery Burst

| | |
|---|---|
| **Tactic** | Discovery |
| **Technique** | [T1087.001 Account Discovery: Local Account](https://attack.mitre.org/techniques/T1087/001/) |
| **Data source** | auditd `EXECVE` records → `index=atomic sourcetype=auditd` |
| **Status** | ✅ Validated 2026-09-22 |
| **ESCU comparison** | Not yet recorded |

## Hypothesis

A single read of `/etc/passwd` is normal. **Several different account-enumeration commands on one host within a few minutes** is discovery.

## Detection (SPL)

```spl
index=atomic sourcetype=auditd type=EXECVE
    a0 IN (cat, head, tail, less, more, grep, awk, cut, lastlog, getent, groups)
| eval args=mvappend(a1, a2, a3, a4)
| eval sensitive=mvfilter(match(args, "^/etc/(passwd|group|shadow|sudoers)$"))
| eval signal=case(
    isnotnull(sensitive), a0.":".mvindex(sensitive, 0),
    in(a0, "lastlog", "getent", "groups"), a0)
| where isnotnull(signal)
| eval event_time=_time
| bin _time span=5m
| stats dc(signal) AS distinct_signals, values(signal) AS signals, min(event_time) AS first_seen BY _time, host
| where distinct_signals >= 3
| convert ctime(first_seen)
```

**Logic:** three or more *distinct* enumeration behaviors per host per 5-minute window.

## Validation

Atomic Red Team `T1087.001` ran at 23:25:36 UTC. It executed `cat /etc/passwd`, `cat /etc/sudoers`, `grep x:0: /etc/passwd`, `grep *:0: /etc/passwd`, `id -u -n`, `lastlog`, `groups` and `id`.

The detection returned **one row with 5 distinct signals**:

```
cat:/etc/passwd  cat:/etc/sudoers  grep:/etc/passwd  groups  lastlog
first_seen: 23:25:36.407
```

## Tuning decisions

| Decision | Why it's safe |
|---|---|
| `id` excluded from scoring | Benign tooling runs it constantly — the PowerShell installer ran `id -u` with no attacker involved. Enough other signals remain. |
| Match file paths in `a1`–`a4`, not just `a1` | `grep` puts the file in `a2`. A first draft checked only `a1` and missed both greps. |
| Count `dc(signal)`, not events | An admin reading `/etc/passwd` five times is one signal and doesn't fire. |
| Ignore the test's `/tmp/T1087.001.txt` output | Keying on it would only ever catch the test itself. |
| `first_seen` captured before `bin` | `bin` rounds `_time` to the bucket, which would hide the real start time. |
| No read watch on `/etc/passwd` | Reads are constant in normal operation; the command line is the better signal. |

## Known gaps

- A burst straddling a 5-minute bin edge can split into two rows that each fall below 3. **Fix when scheduled:** run every 5 minutes over the last 10.
- Enumeration done in-process (PowerShell, Python, libc `getpwent`) spawns no `cat`/`grep` and is invisible here. **Follow-up:** a read watch on `/etc/sudoers` as a second, low-noise detection.
